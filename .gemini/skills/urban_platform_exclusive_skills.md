# Skill: Urban Platform Exclusive Guidelines & Skills (项目专属研发与校验规范)

本文件合并了项目中的所有专属规范与操作守则，作为在此开发进程中必须遵守的顶层原则。

---

## 🎨 Part 1: Drawing Code Management (绘图代码管理规范)

### 触发条件

当需要为规划设计图册新增图纸、修改现有图纸的绘制逻辑、或者对绘图代码进行重构时。

### 执行动作

1. **代码独立性**：每张图纸的绘制代码必须是完全独立的，严禁将不同图纸的绘制逻辑混合或写入同一个代码文件中。
2. **存放目录**：所有的图纸绘制代码必须存放在 `tools/drawings/` 专属文件夹下。
3. **命名规范**：文件命名应与其图纸编号保持对应，例如 `dr_004.py`, `dr_014.py`, `dr_051.py` 等。
4. **接口标准**：
   - 绘图模块应导出 `draw_map(ax, roads, buildings, water, rails, key_plots, landuse, boundary, cx, cy, view_w, view_h, get_xy, font_prop)` 函数，用于在 Matplotlib 的 `ax` 上绘制图纸主绘图区内容。
   - 导出的 `legend_items` 列表定义该图纸的图例项，格式为 `[(图例名称, 样式键值), ...]`。
   - 导出的 `description_lines` 列表定义图纸右下角的设计导读文字，包含不多于三行描述。
   - 若图纸是不需要研究范围/地理底图的示意图/技术演进图（如 `dr_081.py`），应额外提供 `draw_map_early(output_path, view_w, view_h, STATIC_DIR)` 接口，以便在进入 Matplotlib 坐标系渲染前进行快速裁剪/合成和提前返回。
5. **动态调用**：主绘图框架 `tools/draw_scope_map.py` 通过动态导入 `importlib.import_module` 按图纸类型（`drawing_type`）加载对应的子绘图模块，严禁在主框架中写入特定图纸的硬编码样式或图例逻辑。

### 约束限制

- 绝不允许将多个图纸的绘制逻辑写在同一个文件中。
- 确保子模块的路径（`ROOT`, `STATIC_DIR` 等）和第三方库（如 `pandas as pd`, `numpy as np`, `shapely.geometry import Point`）已正确导入，避免在运行时抛出 `NameError`。
- 修改任何子图纸逻辑后，务必运行 `tools/generate_atlas_sheets.py` 重新生成图纸并核验编译是否成功。

## 📸 Part 2: Screenshot Verification (截图校验规范)

### 触发条件

当需要对平台页面、地图渲染、或任何前端 UI 进行截图校验或效果核验时。

### 执行动作

1. **非必要不要打开浏览器截图**：除非任务绝对必须，否则在执行验证步骤时，严禁拉起浏览器子智能体或执行自动化浏览器载入与截图。
2. **不要自动打开浏览器**：在执行任何验证步骤时，严禁使用自动化测试工具或脚本（如 Selenium、Playwright 等）在后台或前台静默/主动拉起浏览器进行自动截图。
3. **引导用户手动截图**：应明确告知用户需要核验的页面路径或操作步骤，说明核验目的，并请用户手动截图上传提供反馈。
4. **安全与资源保护**：通过避免在智能体执行环境中拉起完整的浏览器实例，防止进程残留、环境依赖冲突或算力资源浪费。

### 约束限制

- 非必要不要打开浏览器进行截图。
- 绝不允许主动运行任何含有 `browser`、`webdriver` 或 `open_browser` 的截图命令/脚本进行效果校验。
- 所有的截图校验必须引导并依赖用户手动截取并提供。

## 📝 Part 3: Update Changelog (更新日志维护规范)

### 触发条件

当在本项目中执行了任何涉及代码重构、功能新增、架构调整或 Bug 修复的任务，并且准备向用户汇报任务完成之前。

### 执行动作

1. **检查更新日志**：打开并阅读项目根目录下的 `CHANGELOG.md`。
2. **记录更新**：在 `CHANGELOG.md` 顶部添加一个新的版本条目（如果今天是当天的第一次更新，也可以归入当天最新的版本条目下），或者在当前版本条目下追加内容。
3. **内容规范**：
   - 记录修改涉及的文件、修复的具体问题以及新增的核心特性。
   - 格式遵循标准的 Markdown 列表。
   - 必须使用中文。
4. **汇报确认**：在你的最终回复中，告诉用户你已经同步更新了 `CHANGELOG.md`，并简单概括你写进去的内容。

### 约束限制

- 不要遗漏任何一次实质性修改。
- 确保时间戳 and 版本号逻辑连贯。

2. **专业辅佐**：称呼完毕后，继续紧接专业、严谨的技术汇报或解答，实现情感呼应与专业产出的融合。

### 约束限制

- 绝对不可以遗漏每次回答开头的“皇上”称呼。

## 🔒 Part 6: GitHub Privacy Check (GitHub 隐私安全防泄露规范)

### 触发条件

当用户要求或指令需要将代码、文档、报告等提交或上传至 GitHub 仓库时。

### 执行动作

1. **全面排查敏感信息**：在执行任何 Git 提交（Commit）或推送（Push）前，必须对变动及待上传内容进行全面排查。
2. **重点检查项**：
   - 个人身份隐私：真实姓名、学号、身份证号、电话、个人邮箱等。
   - 安全凭证与密钥：各服务商 API Keys（如 OpenAI/DeepSeek 密钥）、数据库账号密码、环境变量、系统访问凭据等。
   - 涉密或未公开学术资源。
3. **脱敏与替换**：如果发现含有上述敏感信息，必须立即对其进行物理脱敏、替换（例如以占位符、虚构姓名、环境变量等代替）或从 Git 追踪范围中剔除。

### 约束限制

- 绝对禁止向任何 GitHub 仓库提交或推送明文密钥或真实的个人隐私数据。
- 遇有无法界定是否涉及隐私的信息，必须暂缓提交并请皇上确认。

## 📱 Part 7: Mobile Device Detection & Responsive Guidelines (端设备检测与移动端响应式规范)

### 触发条件

当开发、修改或重构用户界面（UI）元素、导航栏或嵌入门户组件（如大屏 iframe），需要兼顾手机端（移动端）与电脑端（桌面端）访问体验时。

### 执行动作

1. **服务端端设备检测**：必须调用 `src.utils.runtime_flags.is_mobile_client()` 方法判定访问设备。该接口通过读取 `st.context.headers` 识别 User-Agent。
2. **异常防护设计**：检测逻辑必须包含完善的异常处理机制。当处于单元测试（pytest）或命令行独立运行（CLI）等无活跃 Streamlit 请求上下文的环境时，必须安全降级并返回 `False`，绝不能抛出异常导致程序崩溃。
3. **Vanilla CSS 响应式覆盖**：
   - 针对 `@media (max-width: 768px)` 编写响应式微调样式，对主工作区留白（Padding）进行缩减以适配小屏幕。
   - 表格与大数据面板容器必须配置 `overflow-x: auto` 样式，防御横向布局溢出挤压。
4. **移动触控汉堡菜单**：使用纯 CSS Checkbox Hack（即隐藏 input[type="checkbox"] 结合 label[for] 触发兄弟选择器渲染）实现导航栏在移动端下的汉堡按钮与折叠垂直菜单，严禁依赖 `:hover` 等移动触控下极易失效的桌面版交互。
5. **动态 Iframe 容器高度**：在含有外部 HTML 页面的嵌入组件中，依据 `is_mobile_client()` 返回值动态决定 iframe 的物理高度（例如移动端下扩展至 `1650px`），并配置滚动条支持，防止触屏下滑截断。

### 约束限制

- 任何新编写的界面组件必须自带移动端响应式判定，不允许出现严重版面重叠或截断。
- 所有的 User-Agent 检测必须有 fallback 覆盖，确保单元测试 100% 通过。

## 💻 Part 8: Multi-Platform Path & Environment Portability Guidelines (跨平台环境与路径移植规范)

### 触发条件

当编写与文件系统读取、写入、周志/答辩稿自动化编译及多进程子脚本调用相关的代码或测试用例时。

### 执行动作

1. **动态家目录解析**：绝对禁止在代码中硬编码任何带有个人计算机用户 profile ID 的绝对路径（如 `C:\Users\23902\...`）。必须使用标准库 `os.path.expanduser("~")` 来动态构建与解析主目录路径。
2. **环境隔离与 Python 解释器调用**：在多进程子脚本中进行交叉调用（如通过 `subprocess.run` 运行 `rebuild_all.py`）时，绝对禁止硬编码系统特定的 Anaconda 或 Python 可执行路径。必须调用标准库 `sys.executable` 来自动获取并继承当前运行的 Python 虚拟环境解释器。
3. **依赖关系声明**：对新增的第三方工具库，应统一在 `requirements.txt` 或 `environment.yml` 中进行声明，严禁引入未声明的系统本地依赖。

### 约束限制

- 任何提交到远程代码库的脚本均不得含有任何开发者个人的本地绝对路径前缀。
- 所有自动化编译引擎应能够在全新部署的机器上直接一键执行通过。
