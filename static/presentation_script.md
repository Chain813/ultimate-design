### ⏱️ [0:00 - 0:45] 第一部分：开场致谢与项目概况

**【展示画面建议】**：PPT 首页，展示项目名称、吉林建筑大学/AI城市诊断实验室署名，以及长春伪满皇宫周边 170.2 公顷研究范围的 3D 数字孪生底座动态旋转动效。

**【汇报台词】**：
各位老师、评委专家，大家（上午/下午）好！

今天我汇报的毕业设计题目是**《数字孪生·古今共振——AI赋能下的城市微更新规划设计决策支持平台》**。

本课题以长春市宽城区**伪满皇宫周边 170.2 公顷街区**为实证研究对象。这里作为典型的历史文化敏感街区，承载着伪满皇宫博物院等核心历史文脉，但现状面临着极为复杂的多维困境：铁路割裂严重、老龄化率高达 30% 以上、生活服务 POI 严重匮乏、街道绿视率（GVI）普遍低于 15%。

针对这种“点状病灶错综复杂”的现状，传统的城乡规划方法往往流于单向灌输和静态蓝图。为此，我开发了 **UltimateDESIGN —— 一站式 Streamlit 全栈决策支持平台**。平台将城市设计拆解为 14 个标准化阶段，打通了“GIS数据采集 → 循证潜力诊断 → 多主体博弈决策 → AIGC空间对齐制图 → 导则与图则智能化交付”的完整闭环，用数据精算、以算法决策、凭真诚守护。

### ⏱️ [0:45 - 2:00] 第二部分：逻辑架构与技术路线

**【展示画面建议】**：系统技术路线图与三层解耦的逻辑架构图。突出 Streamlit、Ollama、Stable Diffusion 以及数据与逻辑分离的机制。

**【汇报台词】**：
支撑这一庞大平台运行的，是**“数据-逻辑-展现”三层彻底解耦**的先进软件工程架构。

首先，在**技术路线**上：
* **前端交互层**：基于 **Streamlit** 构建高响应度的全栈 Web 界面，避免了繁琐的传统前端开发；
* **三维渲染层**：采用 **Deck.GL与Pydeck**，将建筑层高按标准 3.5 米拉伸，构建了 3D 数字孪生底座；
* **大模型推理层**：挂载本地 **Ollama** 引擎（运行 `deepseek-v4-pro` 或 `Gemma` 模型），保证数据隐私与零显存消耗的云端备份；
* **图像生成层**：通过 API 挂载本地 **Stable Diffusion WebUI** 渲染管线，利用 ControlNet 进行地理空间几何对齐。

其次，在**逻辑架构**上，系统由下至上分为三层：
1. **数据层 (Data Layer)**：高度结构化。包含 6 类核心 GeoJSON 空间矢量图层（边界、建筑基底、路网、轨道等）、街景图像切片、POI 和流量数据，以及存放政策规章的本地 RAG 知识库。**数据与逻辑的彻底解耦，意味着当需要迁移到新城市时，只需替换 `data/` 目录，核心逻辑无需修改即可秒级复用。**
2. **计算/引擎层 (Engine Layer)**：集成在 `src/engines/` 中。包含 GVI/SVF 街景图像分割、基于 AHP 的微更新潜力指数（MPI）测度、空间句法拓扑网络分析、RAG 向量检索等 19 个专业计算引擎。
3. **工作流层 (Workflow Layer)**：通过全局数据总线（`stage_data_bus.py`）管理 Stage 00 到 16 的状态流转，实现数据的上游生产与下游消费。

### ⏱️ [2:00 - 3:45] 第三部分：核心亮点与数据处理手段

**【展示画面建议】**：切换到平台核心亮点页。左侧展示 GVI/SVF 街景诊断热力图，右侧展示多角色博弈协商动态雷达图及 SD-ControlNet 渲染管线流程图。

**【汇报台词】**：
在这一架构下，平台实现了四大核心技术突破，这也是我的微更新平台的最大亮点：

* **亮点一：多维指标融合的循证诊断手段。**
  我不再凭经验直觉做规划。平台调用 `site_diagnostic_engine.py`，利用街景图像分割算法批量识别绿视率（GVI）与天空开敞度（SVF），并结合社交媒体舆情（NLP 情感分析得分）与 POI 活力。引入**动态层次分析法（AHP）**加权，计算出每个地块的**微更新潜力指数（MPI）**。例如，平台精准锁定了“食品调料大市场”与“中石油闲置地块”为最高优先级更新单元，并分析出 1062 条路段的空间句法整合度，优化慢行断头路。
* **亮点二：多主体决策博弈推演系统。**
  我们将静态规划升级为“三角色循环博弈模式”。在 Stage 07 中，系统模拟**居民代表老王**（诉求低价业态与生活保障）、**文旅运营商赵总**（诉求商业盈利与长期租约）及**规划师李工**（诉求合规性与公共利益）。三方展开三轮辩论，自动检索 RAG 政策法规库纠偏，最终定量输出**三方共识度雷达图**与**设计策略落地矩阵**，将社会学协商直接转化为控规指标。
* **亮点三：首创 GIS-to-AIGC 空间对齐制图管线。**
  针对生成式 AI 绘图普遍存在的“空间幻觉”，我构建了**“矢量→光栅→ControlNet”**管线。将 GeoJSON 路网骨架光栅化为 Canny 边缘图，将用地分区光栅化为 Seg 语义图，与大模型自动翻译的设计 Prompts 一同送入 Stable Diffusion，在严守地理边界的前提下，渲染出竞赛级的意向总平面图与街景效果图。
* **亮点四：双重质量闭环评估。**
  引入 Gemma 视觉大模型评估图纸图像质量，结合 DeepSeek 进行文本合规性审查。评级为 C/D 的图纸自动被系统拦截，并自动重组 Prompt 重新生成，确保最终交付的 26 张 A3 专业图纸 100% 符合工程设计标准。

### ⏱️ [3:45 - 5:00] 第四部分：与传统规划制图的本质区别

**【展示画面建议】**：对比表格。传统制图（CAD/GIS/静态/主观/图文分离） VS 本平台（数字孪生/动态/循证/多方博弈/DesignContext 统一）。

**【汇报台词】**：
本平台与传统规划制图相比，存在着四个维度的本质区别：

1. **从“静态图版”到“动态数字孪生”**：
   传统制图交付的是 CAD 或 PDF 静态图版。而 UltimateDESIGN 构建了实时交互的数据底座。当开启街景空间品质图层时，平台会自动触发“玻璃化”渲染，使 Deck.GL 建筑模型的透明度从 `0.95` 降低至 `0.28`，呈现精致的通透玻璃感，使底部的 2D 评价热力云图清晰透出，完美解决了高大建筑对环境指标的可视化遮挡。
2. **从“图文脱节”到“DesignContext 设计纲要联动”**：
   传统规划的说明书文字和 CAD 图纸是分裂的。我首创了 `DesignContext`。大模型在前期生成的文本指标（如容积率、绿地率、建筑限高）会实时写入上下文，生图引擎根据上下文数据自动重写 Prompt 提示词，实现图纸与说明书文本的“百之分百空间对齐与语义吻合”。
3. **从“主观灌输”到“多方协商图则化”**：
   传统方案常忽略民意，而本平台将博弈中共妥协的“新派邻里市集40%公益区”、“20年长期租赁协议”、“18米限高与不计容面积奖惩”等白纸黑字直接固化进用地规划条件，使图册（26张专业图纸）真正成为博弈契约的法制化表达。

### ⏱️ [5:00 - 6:00] 第五部分：局限性与不足之处

**【展示画面建议】**：不足之处与遗留事项列表，辅以展望。态度诚恳、科学严谨。

**【汇报台词】**：
当然，作为一次前沿性的探索，本系统目前仍存在一些局限性与不足之处：

1. **对本地 GPU 算力依赖较强**：
   AIGC 图像渲染与 LLM 智能体多轮博弈完全依赖本地的显卡算力（如 Stable Diffusion 与 Ollama）。当在缺乏独立显卡的标准云端环境部署时，平台必须自动退回“预置 Demo 演示模式”，这限制了纯云端协同的设计灵活性。
2. **ControlNet 模型映射硬编码限制**：
   目前底层的 `HighPrecisionPipeline` 在空间约束渲染中，对 ControlNet 模型名称（如 `control_v11p_sd15_*`）存在硬编码。对于本地安装了 SDXL、Flux 等不同版本模型权重的用户，需要重构底层代码进行映射适配。
3. **三维数字孪生底座精度受限**：
   当前的 3D 建筑底座主要通过建筑基底要素的 `Floor` 属性乘以标准层高（3.5米）进行拉伸渲染。这种白膜化拉伸手段无法精细呈现长春伪满皇宫等历史建筑复杂的坡屋顶、飞檐细节，也无法完全复现真实的立面肌理材质。
4. **决策生成管道的延迟耗时**：
   由于每次重绘或研判都包含“大语言模型调用 + SD生图接口 + Gemma 视觉模型质量评估”的多级嵌套，生成一张合格图纸的计算耗时在数十秒，在高度实时的多方协同会议中还无法做到瞬时响应。
